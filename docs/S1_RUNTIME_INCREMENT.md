# S1 runtime increment — implementation and evidence

This increment follows `55a1e574a59a88ad3779e473eff4ba98c6cffe9b`. It is not a declaration that S1 is complete. Full-trust APK/dex execution remains in the host process; no sandbox or reliable hot unloading is promised.

## Implemented

- SDK EntryAdapter/EntryHost.ready and minimal Tool/ToolEnv contracts. Entry initialization has a 30-second deadline; ready listeners do not inherit tool deadlines. Late readiness cannot revive a stopped entry. EntryHost.open throws unavailable until a real session backend exists.
- Direct diagnostic tool invocation: default 60-second idle deadline, renewable by progress, and maximum 600-second total duration. Three FAILED/TIMED_OUT outcomes within 30 seconds quarantine that tool identity for the owner lifetime; cancellation/rejection/success do not count. Failure tracking retains at most 32 tool identities and refuses unknown identities when full. Logical terminal and actual exit are distinct. Default approval is denied and input unavailable. This is not the S2 agent, schema validator, resource lease ledger or approval system.
- Process-shared execution allowance: eight entry/tool workers, two per plugin, two cancellation workers; no execution queue. A slot remains occupied through children/finally and cancellation delivery. Lifecycle callbacks separately have four enable workers and two cleanup workers, also without a queue. Saturation is rejected, not interpreted as successful cleanup.
- Synchronous prefs/secrets under dataDir/.theta-settings, hence included in normal data snapshots. Secrets use Android Keystore AES-GCM with plugin-scoped associated data. Same-UID plugins are fully trusted; encryption is not a secrecy boundary between them. Store close admission is nonblocking; admitted IO drains on cleanup workers. Plugin code should access stores off Main; closed owners cannot start new IO.
- Cold-start crash recovery: token-bound crash receipts, OS crash-history correlation, stable-window accounting, escalating code/data skip policy, persistent page-owner suspects, explicit next-cold-start resume. Wall-clock rollback does not invalidate a matching monotonic crash receipt. Force-stop is not counted as a crash. Host recovery does not implement target-process Hook recovery.
- Data crash suspects are disabled and retained as state-only management records before ZIP parsing. Explicit validation, durable enable and successful acknowledgement precede page publication. Tier-two recovery blocks data imports/selections.
- Exact-install opt-in for code-only rollback. Default remains snapshot-or-cancel; publication must commit before code-only consent is effective. Code-only rollback leaves all current private data/preferences/secrets unchanged. Observation notice displays original first successful start; opening UI or restarting does not restart the 24-hour period.
- Host diagnostic UI exposes entry state and worker-produced tool metadata/progress/results without evaluating tool getters on Main. Closing diagnostics requests cancellation but does not free a running slot.
