## User behavior and boundaries

Both chat and image provider settings offer an explicit Fetch models action using the currently entered endpoint/key. Selecting a filtered, scrollable model fills the existing editable model field; manual entry remains available after empty, unsupported or failed discovery. Opening the dialog and editing fields perform no requests. Loading, empty, no-match and sanitized failure states have English/Chinese text. Settings remain unchanged until Save.

The client reuses `OpenAiChatConfig` URL validation/path normalization and `Credentials`/`validApiKey`. GET `/models` uses Bearer authentication with redirects and connection retries disabled; a per-call network-exchange gate also blocks OkHttp's `503 Retry-After: 0` follow-up. Connect/read/call deadlines are 10/15/30 seconds. Response size is capped at 512 KiB (including chunked bodies), JSON nesting at 32, unique model count at 2048 and model identifiers at the existing 256-character setting limit. IDs are deduplicated and sorted; missing/non-string/blank IDs are ignored, unsupported shapes and abnormal identifiers fail closed. Fixed failure categories retain no original response, URL, key, exception cause or suppressed error. Discovery never invokes chat/image generation or writes a ledger/settings record.

Profile/endpoint/key changes, Save and Close cancel discovery and invalidate its revision. The revision guard also rejects non-cooperative late success/failure callbacks. Credentials remain ordinary ephemeral state, never `rememberSaveable`. The dialog reuses Material controls, its existing scrollable content, 48 dp model rows and a bounded lazy results list. Compose's existing lifecycle-owned `rememberCoroutineScope` plus disposal cleanup is used; reference: [AndroidX Effects.kt](https://github.com/androidx/androidx/blob/androidx-main/compose/runtime/runtime/src/commonMain/kotlin/androidx/compose/runtime/Effects.kt), inspected blob `0cf7653b488dfe7221d0338b7c7632d5d8e8463b` (scope cancellation when leaving composition).
